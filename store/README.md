# Small Victories — Print Store

The print store for [smallvictories.com.au](https://smallvictories.com.au/):
framed photographic prints, fulfilled through
[Format Framing](https://formatframing.com.au) (Melbourne), payments through Stripe.

It's static like the rest of the site — no build step, no database — and deploys
with GitHub Pages at `smallvictories.com.au/store/`. Checkout runs on **Stripe
Payment Links**, so no server is required. An optional serverless checkout
function is included if you ever want a cart.

```
store/
├── index.html / style.css / script.js   the storefront (matches the main site's design)
├── theme.js                             the same 🌑/☀️ toggle as the homepage
├── success.html                         post-purchase page
├── config/
│   ├── prints.json                      the photographs for sale (seeded from ../img/)
│   ├── frames.json                      Format Framing colours/sizes/COSTS ← edit this
│   ├── store.config.json                markup, URLs, currency ← edit this
│   └── stripe.json                      generated by the setup script
├── lib/pricing.mjs                      cost × markup → retail price
├── scripts/stripe-setup.mjs             creates Stripe products/prices/payment links
└── api/checkout.js                      optional serverless checkout (Vercel)
```

## 1. Put in the real Format Framing prices

**The costs in `config/frames.json` are estimates** — Format Framing's site blocks
automated access, so live prices couldn't be pulled. Open
[their Online Print and Frame page](https://formatframing.com.au/products/online-print-and-frame),
note the price for each set size you want to offer, and update `costFramedAud`
(then delete the `"estimate": true` flags and set `"costsAreEstimates": false`).

Frame colours (black / white / natural oak) are the same price at Format Framing,
so cost lives on the size, and colour is just a variant choice at checkout.

Adjust your margin in `config/store.config.json`:

- `markup: 2.0` — retail = cost × 2 (keystone). 2–3× is typical for editioned photographic prints.
- `roundUpTo: 5` — prices round up to the nearest $5.

Sanity-check the resulting price table without touching Stripe:

```sh
cd store
npm install
npm run stripe:dry-run
```

## 2. Curate the prints

`config/prints.json` is seeded with all 19 photographs from the homepage, every
size enabled. Deactivate any you don't want to sell (`"active": false`), trim the
`sizes` arrays, rename the `Untitled NN` titles (these become the Stripe product
names), and add descriptions if you like.

## 3. Connect Stripe

1. Create an account at [stripe.com](https://stripe.com) (choose Australia; prices are AUD).
2. Grab your **test** secret key from [dashboard.stripe.com/test/apikeys](https://dashboard.stripe.com/test/apikeys).
3. Run the setup script:

   ```sh
   STRIPE_SECRET_KEY=sk_test_... npm run stripe:setup
   ```

   For every active print × size it creates a Product, a Price, and a **Payment
   Link** that collects an AU shipping address, phone number, and the frame
   colour (dropdown). It writes the IDs and links to `config/stripe.json` —
   commit that file and the storefront's Buy buttons go live.

4. Test a purchase with card `4242 4242 4242 4242`.
5. When happy, activate your Stripe account and re-run with your live key
   (the `--live` flag is a deliberate safety catch):

   ```sh
   STRIPE_SECRET_KEY=sk_live_... npm run stripe:setup -- --live
   ```

Re-running is safe: it updates in place, deactivates old prices when amounts
change, and mints fresh payment links as needed.

## 4. Fulfilment (Format Framing's artist programme)

This is a dropship flow — Stripe takes the money, you place the order with
Format. They have a formal artists' programme for exactly this
([Working with Artists](https://formatframing.com.au)):

**One-time setup**

1. Email info@formatframing.com.au to introduce yourself and formalise the
   arrangement (they reply within two business days).
2. Set up the shared Dropbox folder of high-res, print-ready files with
   filenames matching the store's print titles — then per order you only need
   to reference the filename, no uploads.
3. For editioned work: request blank Certificates of Authenticity with your
   first order and pre-sign them; Format adds title + edition number to the
   back of each frame as orders come in. You keep the edition ledger.
4. Turn on Stripe payment-success emails: Dashboard → Settings →
   **Communication preferences**.

**Each order**

1. Stripe email arrives — note the print, size, frame colour, matte, quantity,
   and the customer's shipping address/phone.
2. Place the matching order on Format's Print & Frame page. In the checkout
   notes: the Dropbox filename, COA + edition number if applicable, and
   white-label/packaging requests.
3. **Billing address = yours, shipping address = the customer's.**
4. Done. Format prints, frames, packages (biodegradable wrap, recycled
   cartons) and ships free express, carbon neutral, fully tracked — you get
   tracking by email, the customer gets a text, and it's at their door within
   two weeks.

## Notes

- **GST**: if you're not GST-registered (under $75k turnover) don't charge it.
  If you are, enable Stripe Tax or set prices as GST-inclusive.
- **Print previews vs print files**: the store previews use the web-res images
  in `img/`. When fulfilling, upload your full-resolution masters to Format
  Framing, not the web files.
- **Optional serverless checkout** (`api/checkout.js`): deploy the `store/`
  folder to Vercel, set `STRIPE_SECRET_KEY` and `ALLOWED_ORIGIN` env vars, then
  set `checkoutEndpoint` in `store.config.json` to
  `https://<your-app>.vercel.app/api/checkout`. Benefit: the frame colour picked
  on the page is passed straight into checkout metadata instead of the customer
  re-selecting it in the Payment Link dropdown.
- Never commit secret keys. Only the publishable data in `config/stripe.json`
  (price IDs and public payment-link URLs) belongs in the repo.
- Local preview: `npm run dev` from the repo root serves the whole site;
  the store is at `/store/`.
